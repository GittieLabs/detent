# Decisions

| D-001 | 2026-11-04 | Vendor defined HID for app traffic | Keyboard emulation; CDC serial | Keyboard leaks keystrokes and can't be told apart from a real keyboard. Serial works but shows up as a tty and is easier to collide with other tools. |
| D-002 | 2026-11-04 | ESP32-S3 with native USB | Classic ESP32 behind a UART bridge | Native USB is required for custom HID and composite devices. |
| D-003 | 2026-11-04 | Tauri 2, Rust backend, TypeScript UI | Native Swift; Electron | Keeps a Windows door open, small binary, Rust fits the device layer. Swift would be simpler for macOS APIs; we accept some objc bridging. |
| D-004 | 2026-11-04 | Unit identity is VID + PID + serial; PID is the model | Mapping by PID alone | Two units of the same model must be distinguishable. |
| D-005 | 2026-11-04 | Volume and mute pass through as Consumer Control from the device | App only volume | Works with the app closed and shows the native HUD. App volume actions still exist for remappable controls. |
| D-006 | 2026-11-04 | Two scopes: Everywhere and Only in app, app wins | Profiles or layers | Covers the CAD case with one concept. Revisit only with real demand. |
| D-007 | 2026-11-04 | Shortcuts via CGEventPost with Accessibility; app automation via AppleScript | AppleScript System Events for keystrokes | CGEvent is faster and more reliable; AppleScript stays the escape hatch. |
| D-008 | 2026-11-04 | Versioned JSON config file | SQLite | Human readable, diffable, trivially exported. |
| D-009 | 2026-11-04 | Dashboard in a Tauri window with no IPC | External browser kiosk mode | One app to manage; remote content stays sandboxed. |
| D-010 | 2026-11-04 | Dev builds signed with Apple Development cert; releases with Developer ID and notarization | Ad hoc signing | Ad hoc signatures change per build and reset Accessibility grants. |
| D-011 | 2026-11-04 | Transport trait from day one | Hardcode hidapi | Bluetooth and multi device later without touching the router. |
| D-012 | 2026-11-04 | Monorepo: app, firmware, protocol | Separate repos | Protocol changes land on both sides in one commit. |
| D-013 | 2026-11-04 | Open source under the GittieLabs GitHub org | Closed source | Matches the maker goal; others can build devices against the protocol. |
| D-014 | 2026-11-04 | PID requested from Espressif's usb-pids program under VID 0x303A | TinyUSB default PIDs; pid.codes under VID 0x1209 | Free, keeps the Espressif VID, avoids colliding with stock firmware on default PIDs. Placeholder PID until the PR merges. |
| D-015 | 2026-11-04 | Encoder has three device side modes: Volume, Menu, Mapped | Encoder always app driven | Volume and menu work with the app closed; Mapped gives apps a scrub or zoom wheel. |
| D-016 | 2026-11-04 | OLED menu split into firmware owned and app owned items | Whole menu in firmware | Adding an app to the menu is a config change, not a flash. |
| D-017 | 2026-11-04 | Plasticity is the first app scope target | FreeCAD, KiCad, Fusion | Keith's daily tool, and it's shortcut driven, which exercises Send shortcut directly. |
| D-018 | 2026-11-04 | Dashboard URL is a per action setting with no default | Hardcoded Homepage URL | The Homepage container isn't set up yet and its address will change. |
| D-019 | 2026-11-04 | Project name Detent, repo `gittielabs/detent` | Knurl, Switchyard, Patchbay, Pullup, Throw | Knurl is taken by an existing open source macOS macro pad app; Switchyard and Patchbay are crowded. Detent names the encoder's physical click. |
| D-020 | 2026-11-04 | Rust edition 2021 across the workspace, set once in `[workspace.package]` | Edition 2024 | Matches what the Tauri 2 scaffold generates, so the app crate needs no edition migration. Revisit when the Tauri templates move to 2024. |
| D-021 | 2026-11-04 | Enforce the no `unsafe` rule with a workspace `unsafe_code = "deny"` lint; `app/src-tauri/src/macos/` opts in with `#![allow(unsafe_code)]` | Rule by convention only; `forbid` | A lint catches violations in CI. `forbid` can't be overridden per module, so the macos module couldn't opt in. |
| D-022 | 2026-11-04 | Hide the Dock icon two ways: `LSUIElement` in `app/src-tauri/Info.plist` and the Accessory activation policy at startup | Plist only; activation policy only | The plist hides the icon from the first frame of a bundled launch. `tauri dev` runs an unbundled binary that never reads the plist, so the runtime policy covers dev runs. |
| D-023 | 2026-11-04 | Minimum macOS 13.0 | macOS 12 | Launch at login uses SMAppService (architecture), which needs macOS 13. |
| D-024 | 2026-11-04 | Call `AXIsProcessTrusted` through a hand written `extern "C"` block in `macos/` | `accessibility-sys` or `macos-accessibility-client` crates | One function doesn't justify a dependency, and keeping the raw FFI in our own module keeps every unsafe call reviewable in one place. Revisit when CGEvent and CoreAudio bridging grows. |
| D-025 | 2026-11-04 | `build-dev.sh` makes a debug profile bundle | Release profile | Faster rebuilds during the M0 grant test and later dev loops. The TCC grant follows the signing identity and bundle ID, not the profile. Release and notarized builds get their own script in M7. |
| D-026 | 2026-11-04 | Placeholder PID `0x8FDE`, near the top of `0x8000..0x8FFF` | The next sequential free PID (`0x83EB`) | Espressif allocates sequentially from the bottom (highest was `0x83EA` on 2026-11-04). A sequential pick could be handed to someone else before our PR merges; one near the top won't be reached for years. The real allocation replaces it (D-014). |
| D-027 | 2026-11-04 | Message types as plain `u8` constants in `protocol::msg`, with an `ALL` table | A Rust `enum` with `TryFrom<u8>` | Constants map one to one onto the generated C header and keep unknown bytes representable for the codec to reject. The codec in M1 can add an enum on top. |
| D-028 | 2026-11-04 | Firmware pinned to `platformio/espressif32 @ 7.0.1` (Arduino-ESP32 2.0.17) | pioarduino platform with Arduino-ESP32 3.x; unpinned platform | The official platform is already installed on the build Mac and CI can fetch it by exact version. 2.0.17 has the TinyUSB vendor HID and Consumer Control classes M1 needs. Revisit if M1 hits a core bug fixed only in 3.x. |
| D-029 | 2026-11-04 | TinyUSB on the OTG peripheral (`ARDUINO_USB_MODE=0`), CDC on boot off, VID/PID set in `setup()` before `USB.begin()` | Board default USB-Serial-JTAG mode; overriding `USB_VID`/`USB_PID` with build flags | JTAG mode can't do custom HID. The XIAO variant header hardcodes Seeed's IDs, so build flags would be overridden; setting them at runtime before USB starts is the core's supported path. A CDC interface stays so uploads auto reset. |
| D-030 | 2026-11-04 | Generate the C header from a Rust function (`protocol::header::c_header`, run by the `gen-header` bin) and test it byte for byte against the committed file | cbindgen; a shell script that greps the Rust source | The header is `#define`s only, so cbindgen's type machinery buys nothing and adds a dependency. Grepping source breaks on formatting. A function reads the real constants, and the test catches any drift with no extra tooling. |
| D-031 | 2026-11-04 | CI runs two parallel jobs, both on `macos-latest`: Rust and UI, and Firmware. PlatformIO pinned to 6.1.19 | Firmware job on `ubuntu-latest`; one sequential job | The roadmap names `macos-latest`, and matching Keith's Mac avoids Linux only toolchain surprises. Macos minutes cost more on a private repo but are free once it's public. Parallel jobs keep the slow PlatformIO cold start off the Rust path. `just ci` runs the same checks locally. |
| D-032 | 2026-11-04 | Make `gittielabs/detent` public now, before the name and trademark check | Keep it private until the check is done | Keith's call: the repo is unlikely to be found soon, a rename of app and repo is cheap this early, and public CI minutes on macOS are free. |
| D-033 | 2026-11-04 | Apache-2.0 for app, firmware, and protocol, one `LICENSE` file, "Copyright 2026 GittieLabs" | MIT; dual MIT OR Apache-2.0 | Keith's call: match GittieLabs' copperplane. Apache-2.0 also carries an explicit patent grant, which suits a hardware protocol others build devices against. |
| D-034 | 2026-11-04 | `ctl-probe` opens the device with hidapi directly in M1; the app's `DeviceTransport` trait (D-011) is built in M2 and the probe may move onto it then | A shared transport crate now | M1 needs a probe before the devices module exists, and designing the trait before the HID layout spike settles would likely mean redesigning it. |
| D-035 | 2026-11-04 | Firmware logic lives in pure C++ libraries (`firmware/lib/`) tested with PlatformIO's `native` env, and report packing is checked byte for byte against golden vectors generated from the Rust codec | On device tests only; hand written C++ test bytes | Native tests run in CI without hardware. Generated vectors keep the C++ and Rust codecs from drifting, like the header test does for constants. |
| D-036 | 2026-11-07 | One HID interface carrying two collections: vendor channel (usage page `0xFF00`, report ID 6, 63 byte reports) and Consumer Control (report ID 4), plus CDC. Hosts open it non exclusive and drop reads not starting with `0x06` | Two HID interfaces with 64 byte reports and no report IDs, via ESP-IDF `esp_tinyusb` or a custom TinyUSB class driver | The precompiled TinyUSB in Arduino-ESP32 2.0.17 (D-028) has `CFG_TUD_HID = 1`. The spike showed option A works on the XIAO: reads and writes round trip in about 1 ms, opening needs no Input Monitoring (checked from a process never granted it), and the volume keys keep working while the vendor channel is open shared. Option B meant a new toolchain for no user visible gain. Costs: payload drops from 60 to 59 bytes (HELLO's 27 controls and TEST_INJECT's 11 events still fit) and every host write must carry report ID 6, or it is silently dropped. |
| D-037 | 2026-11-07 | Strict decoding: `len` must equal the message's exact size, enum bytes must be defined values, bytes after the payload must be zero, HELLO control IDs must be unique, ENCODER delta can't be zero. The encoder refuses anything the decoder would reject | Lenient decoding that ignores extra bytes and unknown values | The version byte already handles evolution, so v1 has no forward compatibility to preserve. Strict rejection catches firmware bugs at the first report instead of as odd behavior later, and the Debug view can show exactly which rule failed. |
| D-038 | 2026-11-07 | OLED text is printable ASCII only (`0x20..0x7E`) in fixed width, zero padded fields; menu labels 1 to 16 chars, status 0 to 20; `Label` and `StatusText` validate on construction so invalid text can't be encoded | Any byte 0 to 127 ("ASCII"); validating only at encode time | Control characters have no glyph on the SSD1306 font and would render as garbage. Validating at construction puts the error where the UI collects the text, not deep in the send path. |
| D-039 | 2026-11-07 | The firmware's C++ parser must reject malformed reports with the same error kind as Rust: reject vectors carry Rust's verdict, and the C++ checks run in the same order | C++ only has to reject, with any error | Matching kinds keeps the two decoders behaving identically, not just agreeing on accept or reject, so a log line from either side means the same thing. It costs nothing beyond keeping the check order aligned, which the vectors enforce. |
| D-040 | 2026-11-07 | The firmware reads the base MAC and formats the USB serial itself (`lib/usb_identity`, natively tested), then sets it with `USB.serialNumber()` | The Arduino core's `__MAC__` default, which happens to produce the same string | Unit identity (D-004) depends on this string. Owning it means a core upgrade can't silently change the format and orphan every pairing, and the format is covered by a native test. |
| D-041 | 2026-11-07 | `ctl-probe` parses its arguments by hand | `clap` | Three commands and four flags; a dependency and its compile time buy nothing yet, and the parser is unit tested. Switch if the surface grows past a screen of help. |
| D-042 | 2026-11-07 | Link behavior: HELLO at mount as well as on REQUEST_HELLO; heartbeat scheduled from the previous heartbeat (a late tick sends one, never a burst); seq advances on failed sends; paired resets on unmount | HELLO only on request; a fixed 2 s heartbeat grid with catch up; seq only on successful sends; paired sticky across reconnects | The mount HELLO is free and helps any host already listening. Bursts after a stall would look like a flood in Debug. Gaps in seq are the signal that something was dropped. A new connection may be a different host, so it must ACK again. |
| D-043 | 2026-11-07 | TEST_INJECT: delays are relative to the previous event, a new script replaces a running one, and the injector is compiled in always but constructed disabled unless the `xiao_esp32s3_debug` env sets `DETENT_TEST_INJECT` | Absolute offsets from receipt; queueing scripts; `#ifdef` around the whole feature | Relative delays read naturally in scripts ("up 120 ms after down"). Replace keeps a stuck script from blocking the next test. A runtime flag means release and debug run the same code paths, and the release behavior (drop it) is a native unit test rather than an untested `#ifdef` branch. |
| D-044 | 2026-11-07 | `scripts/hil.sh` trusts a flash only when all four regions verify and the vendor channel re-enumerates, keeps its logs on failure, and waits 5 s after each boot before writing (workaround for the open M1 bug) | Trusting the upload exit code; deleting logs always; writing as soon as the device appears | The exit code lies in both directions on this board. Deleted logs hid the first sighting of the bug. The 5 s wait is temporary and is removed by the fix task. |
| D-045 | 2026-11-07 | Firmware on Arduino-ESP32 3.3.12 (ESP-IDF 5.5.5) from the pioarduino platform `55.03.312-1`, PlatformIO Core 6.2.0 in CI. Supersedes D-028; ends D-044's 5 s settle wait | Stay on 2.0.17 with workarounds (delay replies until incoming traffic is quiet; a host rule to wait for each reply) | On 2.0.17, a device report in flight when a second host report lands never completes and sends stay broken until the CPU resets, so macOS resets the device; it hit after plug-in too, and the app writes REQUEST_HELLO then HELLO_ACK right away. The same firmware and trigger failed 2 of 2 on 2.0.17 and passed 3 of 3 on 3.3.12, and `hil.sh` with no wait passed 3 runs in a row. Workarounds only narrowed the timing and couldn't recover the stuck state. Cost: a community platform, PlatformIO 6.2, and an FS include path the 3.x USB library needs. |
| D-046 | 2026-11-07 | Read host reports from `USBHIDVendor`'s own byte queue (sized for 8 reports, filled synchronously by the USB task) and drop everything queued if the core ever passes on a short report; keep boot and USB diagnostics (`DETENT_DIAG`) in the debug firmware | Copying from the output event's buffer pointer; removing the diagnostics after the fix | The core also pushes every report into a 256 byte queue nobody read, so after four reports it truncated the rest, and the event's pointer into TinyUSB's buffer can be reused before the event is handled. The diagnostics (boot count, reset reasons, send and receive counters, a timeline) are what found the stall; they cost nothing in release. |
| D-047 | 2026-11-07 | Input: 10 ms debounce; table driven quadrature decoding in pin change interrupts, 4 steps per detent, impossible transitions ignored; detents coalesced over 20 ms from when loop first sees one; the encoder push switch is a separate button control (id 6 in the placeholder map); D6/D7 stay free for the UART | 5 ms or 20 ms debounce; polling the encoder in loop(); counting single edges; reporting the push switch as part of the encoder | 10 ms rides out typical tact switch bounce while staying far under the 100 ms press budget. Interrupts don't drop turns while loop() blocks in a USB send (up to ~50 ms observed). A transition table makes contact bounce cancel instead of count. A separate button control lets the push switch be mapped like any button. The free UART is how panic output gets read. |
| D-048 | 2026-11-07 | A long press of the encoder's push switch opens the OLED menu from any mode and closes it back to where it came from; Volume mode mutes on release (not press); in Mapped mode the app always gets the Up after a long press; TEST_INJECT encoder and push events replay through the mode router | A dedicated menu button; double click to open the menu; mute on press; injecting at the protocol level only | The architecture says modes switch from the OLED menu but never said how to reach it while the encoder is in Volume mode. A long press is one hand, needs no extra button, and the 600 ms long press already exists. Muting on release is what keeps a long press from also muting. An unpaired Down would leave a key stuck in the app. Injecting through the router means the HIL tests the real path, including real volume changes. |
| D-049 | 2026-11-07 | Keep the debug build's input trace: pin levels on change and every 3 s, encoder interrupt count, each control event and route, and a pin finder over the unused XIAO pins (D4 to D7) | Removing it once the encoder worked | It found a real wiring mistake (encoder on D4/D5 instead of D8/D9) in one capture, and showed the volume path worked by injecting a turn. Debug only (`DETENT_INPUT_LOG`), so release is unaffected. |
